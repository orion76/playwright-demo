# Format: spec-сценарии

Каждый сценарий — отдельный файл в `app/<route>/spec/<scenario>.md`.
Это эталон поведения — с ним сравнивается реальное поведение в spec-тестах и краш-тестах.

## Что описывать

1. **Шаги пользователя** — последовательность действий и ожидаемых реакций:
   - Заполнить поле → проверить валидацию
   - Нажать кнопку → проверить переход/тост
   - Выбрать опцию → проверить состояние

2. **Ожидаемые реакции**: тосты, сообщения об ошибках, валидация, редиректы

## Формат файла сценария

```markdown
# Название — Описание

1. Открыть `/route`

[region.block]
2. **Ожидание:** `elementName` виден
3. <действие с elementName>
4. **Ожидание:** <результат>

[region2.block2]
5. <действие>
```

- `[region.block]` — неймспейс-блок: все последующие элементы указываются коротко (`elementName`)
- Пустой `[]` или полный путь `header.nav.element` для выхода из неймспейса
- `$user`, `$eventName` — переменные из `.prompt.md`, заменяются при генерации теста

## Сопутствующие файлы

| Файл | Назначение |
|------|------------|
| `spec/<scenario>.md` | Сценарий |
| `spec/<scenario>.prompt.md` | YAML frontmatter: `$user`, `$variables` |

## Соответствие тестов

Каждый файл сценария в `spec/` имеет соответствующий тест в `tests/<route>/ideal/`:

```
spec/invalid-phone.md
  → tests/<route>/ideal/invalid-phone--<viewport>--<role>--<lang>.spec.ts
```

## Применение

- **spec-тест**: сверяет реальное поведение с эталоном
- **краш-тест**: пытается нарушить эталон, проверяет реакцию системы
- **перенос в spec**: если краш-тест подтвердил что реакция корректна — сценарий переносится в `spec/<название>.md`
