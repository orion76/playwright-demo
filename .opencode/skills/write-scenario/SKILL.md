# Write Ideal Scenario

Генерирует файл сценария идеального поведения для роута.

## Входные данные

- `app/<route>/structure.yaml` — регионы, блоки, локаторы элементов
- `app/<route>/_prompt.md` — список сценариев роута
- `app/<route>/_status.yml` — статусы сценариев
- `app/<route>/spec/<scenario>.prompt.md` — (опционально) уточнения и переменные (`$user`, и т.д.)

## Процесс

1. Прочитай `_prompt.md` и `_status.yml` — определи, какие сценарии требуют генерации (статус `planned`).
2. Прочитай `structure.yaml` — регионы, блоки, локаторы.
3. Если есть `<scenario>.prompt.md` — прочитай и учти как доп. контекст (переменные `$user`, и т.п.).
4. Сгенерируй `spec/<scenario>.md`:

   ### Язык
   - Сценарий пиши на **русском языке**
   - Шаги — на русском, **Ожидание:** — на русском

   ### Формат
   ```markdown
   # <Название> — <описание>

   1. <действие>

   [region.block]
   2. <действие>
   N. **Ожидание:** <результат>

   [region2.block2]
   N. <действие>
   ```

   - **Неймспейс-блоки:** `[region]` или `[region.block]` задаёт контекст для следующих шагов
   - Внутри блока элементы указываются коротко: `phoneInput`, `continueBtn` (без префикса `main.phoneForm.`)
   - Для выхода из неймспейса — пустой блок `[]` или полный путь `header.nav.element`
   - Если элемент вне текущего неймспейса — используй полный путь: `header.nav.organizers`

   ### Правила
   - Опиши последовательность шагов пользователя
   - Для каждого шага укажи: действие (заполнить поле, нажать кнопку, выбрать опцию) и ожидаемый результат (тост, редирект, ошибка, видимость элемента)
   - Используй конкретные данные: `PLAYWRIGHT-TEST-{Date.now()}` для уникальных значений
   - Ссылайся на элементы по идентификаторам из `locators.yml` (например `phoneForm.phoneInput`, `generalInfo.next`)
   - Если сценарий описывает валидацию — укажи точный текст ожидаемой ошибки
   - **Не используй константы** — используй переменные из `.prompt.md` (`$user`, `$eventName`)
   - Не добавляй лишних шагов, которых нет в структуре страницы
