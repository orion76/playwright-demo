Верни список тестов, отфильтрованный по параметрам.

Параметры (передаются в `$ARGUMENTS` через пробел, парсить вручную):
- `r=<route>` — роут (например `r=products`, `r=_home`)
- `t=<scenario>` — имя сценария (например `t=search-product`)
- `s=<status>` — статус из `_status.yml` (например `s=planned`, `s=base_test_generated`)
- `v=<viewport>` — viewport (например `v=desktop`, `v=mobile`, `v=tablet`)
- `u=<role>` — роль пользователя (например `u=guest`, `u=registered`)
- `l=<lang>` — язык (например `l=en`)

Фильтрация:
- Если `r` задан — только тесты в `tests/<r>/ideal/`
- Если `t` задан — только тесты с `<t>` в имени файла (match по подстроке)
- Если `s` задан — прочитать `app/<r>/_status.yml` (или все `app/*/_status.yml` если `r` не задан), оставить только тесты с совпадающим статусом
- Если `v` задан — только тесты с `<v>` в имени файла (часть после `--`)
- Если `u` задан — только тесты с `<u>` в имени файла (часть после второго `--`)
- Если `l` задан — только тесты с `<l>`, после названия файла (перед `.spec.ts`)
- Если ни один параметр не задан — все тесты из `tests/`

Формат вывода — по одному пути на строку:

```
<route>/<scenario>--<viewport>--<role>--<lang>.spec.ts
```

Пример: `r=products s=base_test_generated v=desktop` → все desktop-тесты со статусом base_test_generated в роуте products.
